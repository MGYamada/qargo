# Qargo working guidelines

- Follow QRATEBOUNDARY.md: every internal or external qrate has an independent environment boundary, including its Rust development environment when present. qlippy, qlifmt, and qlidoc are three ordinary qrates; align their versions with Qargo only for bundle convenience, without privilege. Only std is privileged, bundled with and versioned alongside Qleisli. Follow docs/qrate-development.md for the independent Cargo environments and extraction verification.
- For extraction work, enforce the shared-support/linter API separation, wiring-only root adapters, and the acyclic Qargo-to-components dependency direction in QRATEBOUNDARY.md. Bind the complete Rust project inventory and actual build environment separately from existing Qleisli source/qrate input identities. Root Cargo [package].version is the release-orchestration authority; component manifests retain literal versions validated against it.
- Follow docs/architecture.md: Exact, Immutable, Bound, Explicit, Independent. Keep typed requests, immutable captured subjects, checked/validated results, and explicit effects separate. Bind results to actual input/tool identities; publisher authentication belongs to distribution policy, and metadata is not mathematical evidence.
- Qargo manages Qleisli qrates; Cargo builds, packages, and installs the Rust implementation outside Qargo operations. Never invoke Cargo from a Qargo command or translate Qargo test/doc into Rust tests/Rustdoc.
- Starting with 0.1.1, distribute the standard bundle through crates.io under the package name qargo alongside GitHub source releases, installing all four executables. The public package compiles the canonical qrate sources as internal modules; private engine crates remain development-only. A source-archive check does not establish .crate packaging readiness. Validate the packaged sources and installation before publication; version preparation does not authorize publishing.
- Starting with 0.1.5, also distribute native Linux x86_64 and macOS x86_64/ARM64 binary archives, install.sh, and SHA256SUMS. Linux ARM64 is deferred while the exact Qleisli 0.2.1 loader remains incompatible (issue #18). Validate archive inventory, platform linkage, and Cargo-free installation independently. These are implementation distribution operations outside Qargo commands; binary assets require explicit GitHub release authorization before publication.
- The standard bundle comprises qlippy, qlifmt, and qlidoc, developed together at version 0.1.8. Each qrate includes its Rust engine, CLI, Rust test sources, and a minimal src/smoke.qli management sample, with no .qlt files. Shared support belongs to qlippy. Developer Cargo configuration lives outside the qrates in independent rust/<tool>/ workspaces with their own lockfiles and toolchain declarations. Transfer both trees and the explicit dependency closure together during extraction. Use source strings and temporary directories for engine tests; preserve coverage of empty qrate roots.
- Full independent extraction verification is an on-demand workflow, not a push/PR check. Require its complete Linux/macOS × Rust 1.85/stable matrix for every release candidate. Ordinary CI retains lightweight boundary audits and source/package validation; it does not replace the manual release gate.
- Read docs/specification.md before changing public behavior. Manifest and result schema versions are independent of product versions.
- Valid Qargo.toml manifests, documentation examples, and test fixtures must use schema-version = 2 and explicitly declare edition = "2026" under [qrate]. Never omit or infer the Qleisli edition, supply a default, or accept an unsupported edition. Qleisli and Rust editions are independent; keep the Rust implementation's Cargo.toml edition = "2024" explicit.
- Preserve ordinary Qleisli checking and its trust boundary. Empty source roots have no Qleisli checking result. Lint results and build records are metadata, not mathematical evidence.
- Follow docs/ecosystem-policy.md: curated stdlib first; future extensions require trusted sources, authenticated namespaces, and fixed identities. Public registry and automatic semver resolution are deferred. Never introduce arbitrary qrate build hooks, native procedural macros, dependency-install scripts, or global feature unification into Qargo operations. Rust implementation builds remain outside that boundary.
- Follow docs/adoption-plan.md for tooling work: local diagnostic explanations, compatibility comparisons, explicit documentation-example checks, then scoped review records. Toolchain selection, structured repairs, and QLT execution require their upstream protocols and separately specified public contracts; the plan does not implement them or authorize changing the Qleisli dependency pin.
- Follow docs/toolchains.md for qleisliup compatibility. Start with offline proxy/bundle checks; qleisliup selection does not replace the linked Qleisli checker. Do not parse human manager output, couple Qargo to manager state or a qleisliup library, or treat a repository toolchain pin as captured acceptance configuration before its Qargo contract is specified.
- qlifmt and qlidoc use syntax parsing only; their success does not imply type, ownership, or contract verification. qlidoc currently generates Markdown; future HTML may use independent CSS and layout rather than rustdoc's appearance.
- Specifications, public documentation, diagnostics, and code comments are English. User conversation can follow the user's language.
- Rust 1.85 is the MSRV; forbid unsafe code. Keep the Qleisli dependency exactly at 0.2.1.
